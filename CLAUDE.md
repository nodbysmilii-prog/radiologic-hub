  - mettre à jour la date « Dernière mise à jour du README » ;
  - mettre à jour les sections concernées (fiches disponibles, fichiers, code couleur, « À faire »…).

- **Domaine officiel : https://radiologichub.com** (fichier `CNAME`, DNS chez Spaceship, HTTPS imposé). Adresse historique : https://nodbysmilii-prog.github.io/radiologic-hub/ (GitHub la redirige ; elle reste dans les adresses de retour Supabase pendant la transition). Ne jamais écrire l'adresse du site en dur : le site utilise des liens relatifs et l'adresse de la page, les fonctions Supabase le seul secret `RP_URL_SITE` (`https://radiologichub.com`, sans `/` final).
- **Production Supabase** : aucune modification (migration, déploiement de fonction, secret, tâche Cron, envoi réel d'e-mails) sans autorisation explicite de l'utilisateur, étape par étape. L'état réel se lit avec le workflow « Exploitation Supabase » (action `diagnostic`, lecture seule, rapport dans le résumé de l'exécution) ; ses autres actions sont désactivées. Les journaux GitHub Actions sont publics tant que le dépôt est public : n'y afficher que des oui / non, des versions et des dates — aucune information sur les utilisateurs (pas même des comptes), jamais un secret ni une réponse brute. Les workflows Supabase fonctionnent en dépôt privé GitHub Free (pas d'environnement protégé) : lancement manuel par le propriétaire, branche principale seule, déploiement seulement après la confirmation écrite `DEPLOYER`, secret `SUPABASE_ACCESS_TOKEN` (secret du dépôt) donné à une seule étape ; ne jamais ajouter de déclenchement automatique ni afficher un secret. Ne demander aucun mot de passe ni clé dans la conversation.
- **Modules Remplacements et Communauté pas encore en production** : quand l'utilisateur demande les étapes de mise en service (Supabase, les deux migrations, Brevo, connexion Google OAuth, temps réel, secrets, déploiement, planification, administrateur, `config.js`) ou les démarches juridiques (mentions légales, conditions d'utilisation de la Communauté, INPDP, contrat), les lui rappeler à partir de `remplacements/INSTALLATION.md` et de la liste « À faire » du README, en signalant celles qui semblent déjà faites (par exemple `remplacements/config.js` renseigné).
- **Sources de cours** (PDF, notes, synthèses) : les ranger dans le dépôt **privé** `nodbysmilii-prog/radiologic-hub-sources` (dossier `sources/<module>/`, une ligne dans son README), jamais dans ce dépôt public. Rien de ce dépôt privé n'est copié dans le site : seulement du texte **reformulé**.
- **Fiches rapides** : avant toute création ou modification importante de fiche, lire `docs/organisation/CHARTE_FICHES.md` (méthode pédagogique et interactive, composants réutilisables, rigueur médicale : ne jamais inventer ni modifier le fond sans validation de l'auteur).
- **Comptes rendus** : avant toute création ou modification importante (modèle, phrase, outil de score, « en vrac », export), lire `docs/organisation/CHARTE_COMPTES_RENDUS.md` (architecture réelle, conventions, présent vs prévu ; aucune constatation médicale ajoutée à la place du radiologue, contenus validés intacts).
- **Calculateurs et classifications** : avant toute modification importante d'un calculateur, d'un score ou d'une classification, lire `docs/organisation/CHARTE_CALCULATEURS.md` (conventions du code, tests, présent vs prévu ; seuils et textes médicaux jamais modifiés sans validation de l'auteur).
- **Radioanatomie** : avant toute création ou modification importante (atlas, planche, visionneuse, annotations, 3D), lire `docs/organisation/CHARTE_RADIOANATOMIE.md` (moteurs existants, formats, validation anatomique, présent vs prévu, feuille de route ; aucune structure inventée, repères et noms jamais modifiés sans validation de l'auteur).
- **Bibliothèque scientifique** : avant toute modification importante (configuration, import, fiches, filtres, administration, veille), lire `docs/organisation/CHARTE_BIBLIOTHEQUE.md` (classement, références, licences, résumés originaux, composants, présent vs prévu ; aucun PDF, image ni abstract repris, aucune référence saisie de mémoire).
- **Communauté** : avant toute modification importante (fil, profils, messagerie, notifications, modération, annonces de remplacement dans le fil), lire `docs/organisation/CHARTE_COMMUNAUTE.md` (architecture réelle, source unique `rp_demandes` pour les remplacements, confidentialité, interdiction de données de patients, MVP et feuille de route ; ne jamais modifier `rp_*` depuis la Communauté).
- **Publication (site public)** : seul `dist/` est mis en ligne, construit par `npm run publication` depuis la **liste blanche** `scripts/publication/liste-blanche.js`. Nouvelle page à la racine ou nouveau dossier du site → l'y ajouter ; fichiers internes (scripts, SQL, fonctions serveur, docs, tests) → jamais. `npm run publication` doit réussir avant de pousser (échec si fichier interdit, secret ou dépendance manquante). Contenus réservés aux abonnés : jamais dans le site public (`RESERVE_ABONNES`, stockage Supabase privé). Avant toute modification de la publication, de l'hébergement (Cloudflare Pages), du domaine ou des workflows : lire `docs/organisation/PUBLICATION.md`.
- **Gros fichiers tiers** (pack Z-Anatomy…) : dans `assets-sources/` (ignoré par git), retéléchargés par un script à version figée ; seuls les exports dérivés vont dans le site, dans un dossier à part avec leur `LICENSE`.
